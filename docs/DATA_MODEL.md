# AgentDesk — Data Model

Only entities the MVP needs are defined. Everything is in-memory on the laptop; there is no persistence layer yet, so this describes Rust structs (mirrored in Dart where the phone needs them), not tables.

## Entity overview

```text
Agent 1──* Task 1──* Event *──1 QueueEntry
  │                    │
  └── LogBuffer        └── OpenTask (derived, Task Tracker)
Event ──? PinnedLogWindow
Device (1 in MVP) ── Session (connection)
```

## Agent

| Field | Type | Notes |
|-------|------|-------|
| `agent_id` | string | Stable per adapter instance, e.g. `sim-backend`. |
| `name` | string | Human label, e.g. `Backend Agent`. |
| `project` | string | Human label, e.g. `Hybrid`. MVP: one string; a `Project` entity is not needed yet. |
| `adapter_kind` | enum | `simulator` now; `claude_code` later. |

## Task

Tasks are **not stored as an entity** in the MVP. A task is identified by a `task_id` string chosen by the adapter and carried on events. The Task Tracker keeps a derived `OpenTask` while the task is live:

| Field | Type | Notes |
|-------|------|-------|
| `task_id` | string | |
| `agent_id` | string | |
| `title` | string | e.g. `Implement authentication`. |
| `operation` | enum | `build`, `test`, `install`, `analyze`, `edit`, `other`. Drives escalation threshold. |
| `started_at` | timestamp | From first event carrying this `task_id`. |
| `latest_working_event` | event_id | Target for escalation. |
| `escalation_level` | 0..2 | |

## Event

Immutable. See EVENT_MODEL.md for the full schema and semantics.

## QueueEntry

Mutable metadata about a live event; owned by the Priority Queue.

| Field | Type | Notes |
|-------|------|-------|
| `event_id` | uuid | |
| `tier` | 0..3 | Derived from category: request=0, error=1, completed=2, working=3. |
| `score` | u16 | Recomputed on tick. Orders within tier. |
| `state` | enum | `new`, `seen`, `dismissed`. |
| `resolution` | enum? | Requests only: `unresolved`, `approved`, `denied`. |
| `superseded` | bool | Working entries of a closed task. |
| `escalation_level` | 0..2 | Working entries only. |
| `seq` | u64 | Copied from the event for tie-breaking. |

## LogBuffer

One per agent. Bounded ring buffer of `LogLine { offset: u64, ts, text }`. `offset` is a monotonically increasing line counter per agent that does **not** reset on eviction, so `log_range` on events stays meaningful.

## PinnedLogWindow

| Field | Type | Notes |
|-------|------|-------|
| `event_id` | uuid | |
| `start_offset` | u64 | |
| `lines` | Vec<LogLine> | Copied at pin time; survives ring eviction. |

## Device and Session

| Field | Type | Notes |
|-------|------|-------|
| `device_id` | string | Sent in `hello`; MVP uses a random id generated by the app on first run. Informational only — authorization is by token. |
| `connected_at` | timestamp | |
| `last_seq_sent` | u64 | Bookkeeping; used by future offline sync. |

## Command

Phone → laptop messages are transient and not stored beyond metrics counting. See COMMUNICATION.md.

## Metrics

A flat counter struct; see ARCHITECTURE.md. Serialized to JSON by the bench and available at runtime via a `get_metrics` request.

## Not modelled yet

- `Project` as a first-class entity (string on `Agent` suffices).
- `Log` as a stored entity (ring buffer + pins suffice).
- Persistent `Device` registry, permissions, revocation.
